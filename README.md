# 顾问室：利益冲突筛查、受控披露与交接服务

企业先提交咨询事项和资料范围；秘书处在不披露主体身份和文件正文的情况下征询顾问。顾问完成实际参与人员的利益冲突筛查、签署经电子签署终态确认的保密承诺后，企业再按机构/人员、文件版本、章节和用途决定披露范围。更换顾问时，只交接当前仍有逐项授权的资料和工作成果。

> 本项目只使用虚构机构、合成人员和合成文件，不接真实企业数据，也不构成真实法律意见、认证系统或生产身份体系。`X-Actor-Id` 仅是本地验证角色头。

## 快速开始

要求 Node.js `22.23.4`，无第三方运行时依赖。

```bash
npm ci --ignore-scripts
npm run verify     # 语法检查 + 全部测试
npm run dev        # 业务 :4318，电子签署替身 :4317
```

健康检查：

```bash
curl -sS http://127.0.0.1:4318/health
curl -sS http://127.0.0.1:4317/health
```

中文接口手册和完整 curl 流程见 [`docs/api.md`](docs/api.md)；电子签署替身协议见 [`docs/partner.md`](docs/partner.md)；合成数据语义见 [`docs/data.md`](docs/data.md)。

## 本地角色

| `X-Actor-Id` | 身份 |
| --- | --- |
| `client` | 合成企业甲 `ORG-A` |
| `secretary` | 秘书处 |
| `adviser-a` | 干净成员 `USER-A` / `ADV-A` |
| `adviser-b` | 命中合成冲突的 `USER-B` / `ADV-A` |
| `adviser-c` | 后加入/替换成员 `USER-C` |
| `adviser-successor` | 接任顾问 `USER-S` / `ADV-B` |
| `counterparty-b` | 对手方 `ORG-B`，用于书面豁免 |

示例：

```bash
curl -sS -H 'X-Actor-Id: secretary' \
  http://127.0.0.1:4318/api/secretary/engagements | jq '.engagements[0].bottleneck'
```

## 主业务闭环

1. **企业提交事项**：参与企业、对手方、关联主体、专业领域、资料范围。
2. **秘书处盲征询**：顾问只看到 `BLIND-*` 编号、专业领域和资料类别，看不到主体名称或正文。
3. **按实际人员筛查**：机构通过不覆盖后来加入的人；秘书处保管对应关系，顾问只收到“是否需要进一步人工核查”。
4. **人工核查与豁免**：确认冲突后，未经企业和有权对手方书面豁免，不能进入 NDA 后的受托工作/披露。
5. **电子保密承诺**：外部签署服务 `accepted` / `pending` 不等于生效；全部签署项 `confirmed` 并对账后才开通权利。重复通知不能扩张原始人员范围。
6. **企业逐项披露**：按人员、文件版本、章节、`quote` / `perform` 用途和是否允许分包授权。秘书处不能代替企业同意。
7. **真实文件鉴权**：`/api/documents/:id/content` 和分段路径在每次请求、每个输出分块前读取当前状态；不是仅隐藏目录列表。
8. **委托与成果**：企业确认委托后，顾问可提交带资料版本引用的成果；企业可部分接受、要求补充、完成或终止委托。
9. **成员变化/撤权**：旧成员后续下载、断点续传、新分段和新版本请求立即按新状态判断；已发出的旧字节不能声称远程收回，但可查询实际发送范围。
10. **交接**：清单本身不是授权。企业原始资料由企业重新授权给接任者；前任知识成果按转让条件逐项取得企业批准和/或前任放行，接任者签收后完成交接。
11. **费用争议**：可记录未结费用争议，但不能据此继续访问企业已撤回的原始资料。

## 重点边界的自动核对

```bash
npm test
```

`tests/business.test.mjs` 使用临时状态文件、随机本地端口和内置电子签署替身，覆盖：

- 顾问冲突响应和拒绝留痕不泄露秘书处掌握的其他企业名册；
- 双方书面豁免、秘书处不能代替企业披露；
- 签署受理未确认时不生效，重复通知附加人员不扩权；
- 文件版本、章节、用途、标准 `Range`、分段下载和撤权后续传；
- 已披露/已发送字节范围查询；
- 成员替换后旧成员立即被拒、新成员不自动获得授权；
- 成员更换、续传、交接并发时不出现 `500`，状态保持一致；
- 交接清单、逐项企业批准、前任放行、接任委托和签收；
- 费用争议不阻止撤权生效。

## 常用命令

```bash
npm start             # 仅业务服务，默认 :4318
npm run start:partner # 仅电子签署替身，默认 :4317
npm run dev           # 同时启动两者
npm run build         # 对所有 JS 和测试做 node --check
npm run verify        # build + test
PORT=4400 npm start   # 更换业务端口
```

业务服务默认监听 `127.0.0.1`，避免把带模拟角色头的接口暴露到网络。Docker/容器场景可设置 `HOST=0.0.0.0`。

## 持久化与合成资料

- `fixtures/records.json`：虚构组织、事项、人员、文件和草稿。
- `fixtures/partner.json`：电子签署替身协议配置。
- `objects/`：既有合成文本对象。
- `.local/app-state.json`：业务状态，默认不入库。
- `.local/objects/`：运行时上传文件和自动生成的 512 KiB 大型合成文件。
- `.local/partner.json`：电子签署替身流水。

`consentDrafts`、`workDrafts` 和 `sourceChanges` 都只是草稿或来源申请，不会在启动时自动变成企业同意、成果批准、成员加入或豁免决定；必须通过对应业务操作形成决定。
